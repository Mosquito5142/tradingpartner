# ปฏิทินข่าวเทรดทอง XAUUSD

เว็บแอป Next.js — ปฏิทินข่าวเศรษฐกิจเวลาไทย พร้อมกราฟ 15 นาที แนวรับแนวต้าน
และ **Reaction Lab** ที่วัดว่ากฎทิศทางแม่นจริงแค่ไหนจากราคาย้อนหลัง

> ⚠️ เครื่องมือนี้รวบรวมกำหนดการข่าวและวัดสถิติจากราคาย้อนหลัง
> **ไม่ใช่การทำนายราคาและไม่ใช่คำแนะนำการลงทุน**

## ตั้งค่า Turso (คลังสถิติ Reaction Lab)

จำเป็นเพราะบน Vercel ไฟล์ในดิสก์หายทุกครั้งที่ deploy และ Yahoo ให้ข้อมูล
แท่ง 5 นาทีย้อนหลังแค่ 60 วัน — ถ้าไม่เก็บเองตัวอย่างจะไม่มีวันโตพอจะสรุปรายข่าวได้

1. สมัครฟรีที่ [turso.tech](https://turso.tech) แล้วติดตั้ง CLI
2. สร้างฐานข้อมูลและเอา URL กับ token:

```bash
turso db create goldnews
turso db show goldnews --url
turso db tokens create goldnews
```

3. ใส่ลง `.env.local` (และลง Vercel Environment Variables ตอน deploy)

```
TURSO_DATABASE_URL=libsql://goldnews-xxxx.turso.io
TURSO_AUTH_TOKEN=eyJ...
```

4. ย้ายข้อมูล 130 รายการจากเวอร์ชันเดิมเข้าไป (ถ้ามี):

```bash
node scripts/migrate.mjs ../data/reactions.json
```

5. หรือเก็บใหม่จากศูนย์:

```bash
curl "http://localhost:3000/api/collect?backfill=1"
```

ตารางถูกสร้างอัตโนมัติ ไม่ต้องรัน migration เอง

## Deploy ขึ้น Vercel

```bash
npx vercel
```

จากนั้นตั้ง Environment Variables ใน Vercel Dashboard:

| ตัวแปร | ต้องมี | คำอธิบาย |
|---|---|---|
| `TURSO_DATABASE_URL` | ✅ | URL ของ Turso |
| `TURSO_AUTH_TOKEN` | ✅ | token ของ Turso |
| `CRON_SECRET` | แนะนำ | กันคนอื่นเรียก `/api/collect` (Vercel ส่ง header ให้เอง) |
| `BROKER_OFFSET` | ไม่บังคับ | ราคากราฟโบรกฯ ลบด้วยราคา spot (ค่าเริ่มต้น −3.04) |
| `TELEGRAM_BOT_TOKEN` | ไม่บังคับ | เปิดใช้แจ้งเตือน — ไม่ตั้งก็ใช้ส่วนอื่นได้ปกติ |
| `TELEGRAM_CHAT_ID` | ไม่บังคับ | ห้องที่จะให้บอทส่งข้อความเข้า |

`vercel.json` ตั้ง Cron เก็บข้อมูลไว้วันละครั้ง (`0 6 * * *`) ซึ่งเป็นเพดานของแผนฟรี
ถ้าใช้แผน Pro จะปรับเป็นทุกชั่วโมงก็ได้

## Reaction Lab — ทำไมถึงมี

กฎทิศทางใน `lib/bias.ts` มาจากตำรามหภาค พอเอาไปวัดกับราคาจริงพบว่า
(ข่าวใหญ่สหรัฐฯ n=35, แท่ง 5 นาที GC=F):

| หลังข่าว | ทฤษฎีถูก | ขยับมัธยฐาน |
|---|---|---|
| 5 นาที | 66% | $6.60 |
| **10–15 นาที** | **71%** | **$8.90** |
| 30 นาที | 51% | $8.00 |
| 60 นาที | 49% | $13.90 |

**กฎใช้ได้จริง แต่มีอายุราว 15 นาที** ตรวจแล้วว่าไม่ใช่ผลของเทรนด์ขาขึ้น
(เส้นฐาน = ทองปิดบวก 51.2% ของทุกชั่วโมง ส่วนหลังข่าวขึ้น 54%)

**แยกตามกลุ่ม — ต้องดู % ถูก คู่กับระยะที่ขยับเสมอ:**

| กลุ่ม | n | 15 นาที ถูก | ขยับ |
|---|---|---|---|
| ข่าวใหญ่สหรัฐฯ | 35 | 71% | $8.90 |
| ข่าวกลางสหรัฐฯ | 62 | 52% | $6.90 |
| ยุโรป / จีน | 33 | 73% | $4.40 |

ยุโรป/จีนแม่นสูงแต่ขยับแค่ $4.40 ซึ่งเกือบเท่าสเปรด — **ความแม่นที่ขยับน้อยกินไม่ได้จริง**

## โปรไฟล์บัญชี `/profile`

รวมทุกอย่างที่ควรรู้เกี่ยวกับบัญชีไว้หน้าเดียว — **อ่านยอดเงินและข้อมูลบัญชีจากหัวรายงานเอง
ไม่ได้ฝังไว้ในโค้ด** เพราะยอดเปลี่ยนทุกครั้งที่เทรด ค่าที่ hardcode ไว้จะล้าสมัยทันที
และทำให้ %เสี่ยงทั้งเว็บผิดตาม

| ส่วน | มีอะไร |
|---|---|
| ยอดเงิน | ยอดปัจจุบัน · เงินบาท · ทุนตั้งต้น (คำนวณจากยอด − กำไรสะสม) · % เติบโต · กำไรเฉลี่ยต่อไม้ |
| บัญชี | เลขบัญชี (แสดง 4 ตัวท้าย) · โบรกเกอร์ · เซิร์ฟเวอร์ · real/demo · Hedge/Netting · สกุลเงิน |
| โอกาสชนะ | อัตราชนะ **พร้อมช่วงความเชื่อมั่น Wilson 95%** — ถ้าช่วงยังคร่อม 50% จะบอกตรง ๆ ว่าสรุปไม่ได้ |
| ความเสี่ยง | ถอยจากยอดสูงสุด (DD) · ไม้แย่สุด · แพ้/ชนะติดกันมากสุด · ล็อตล่าสุดเทียบค่ากลาง · ราคาสวนเท่าไหร่พอร์ตหมด |

**ตรวจสอบแล้วทุกช่องตรงกับที่ MT5 คำนวณเอง** — ยอดเงิน 3,697.20 · กำไรสุทธิ 2,688.20 ·
PF 2.87 · Expected Payoff 116.88 · Balance Drawdown Maximal 741.40 (23.35%) · 23 ไม้
(DD กับ streak เราคำนวณเองจากเส้นกำไรสะสม ไม่ได้อ่านจากรายงาน แล้วได้ค่าตรงกัน)

> ⚠️ เว็บนี้เปิดสาธารณะและไม่มีระบบล็อกอิน — ใครมีลิงก์ก็เห็นยอดเงินและประวัติเทรดได้
> เลขบัญชีจึงแสดงแค่ 4 ตัวท้าย ถ้าไม่อยากให้ใครเห็นเลยควรตั้ง Password Protection
> ใน Vercel (Settings → Deployment Protection)

### ทำไมต้องใช้ Wilson interval

ที่ n น้อย สูตรช่วงความเชื่อมั่นแบบปกติให้ช่วงที่แคบเกินจริงและทะลุ 0–100% ได้
ซึ่งจะทำให้มั่นใจในตัวเลขมากกว่าที่ควร — ปัจจุบันชนะ 15/23 = 65.2%
แต่ช่วงจริงคือ **45–81%** ซึ่งยังคร่อม 50% อยู่ หน้าเว็บจึงบอกตรง ๆ ว่ายังสรุปไม่ได้

## กินได้จริงไหมหลังหักต้นทุน

`71%` ไม่ได้แปลว่ากำไร — แผงนี้ใน [/lab](/lab) แปลงความแม่นเป็นกำไรต่อไม้จริง
พร้อมช่องปรับต้นทุน (สเปรด + slippage) เองเพราะแต่ละโบรกฯ คิดไม่เท่ากัน

**ข่าวใหญ่สหรัฐฯ ก่อนหักต้นทุน (n=35)**

| ออกที่ | เฉลี่ย | มัธยฐาน | SD | ช่วงเชื่อมั่น 95% |
|---|---|---|---|---|
| 5 นาที | +$10.45 | +$3.20 | $28.06 | $1.16 – $19.75 |
| **15 นาที** | **+$10.25** | **+$2.60** | **$29.30** | **$0.54 – $19.95** |
| 30 นาที | +$7.58 | +$0.50 | $27.46 | −$1.52 – $16.67 |
| 60 นาที | +$6.31 | −$0.30 | $27.55 | −$2.82 – $15.43 |

**สามข้อที่เปลี่ยนการตีความ:**

1. **ขอบได้เปรียบเฉียดฉิว** — ขอบล่างของช่วงความเชื่อมั่นที่ 15 นาทีอยู่ที่ $0.54
   แปลว่าต้นทุนเกิน **$0.54/ออนซ์** เมื่อไหร่ ก็หลุดนัยสำคัญทางสถิติทันที
   (แผงจะขึ้น ✓ เฉพาะตอนขอบล่างยังบวก ไม่ใช่แค่ค่าเฉลี่ยบวก)
2. **กำไรมาจากไม้ไม่กี่ไม้** — เฉลี่ย $10.25 แต่มัธยฐานแค่ $2.60
   คนที่เก็บกำไรเร็วทุกไม้จะไม่ได้ขอบได้เปรียบนี้เลย
3. **ต้นทุนกินอัตราชนะด้วย ไม่ใช่แค่กำไร** — ที่ต้นทุน $0.50 อัตราชนะตกจาก 71% เหลือ **60%**
   เพราะไม้ที่ชนะน้อยกว่าต้นทุนกลายเป็นไม้แพ้

**SL แคบคือตายก่อน** — วัดจากระยะที่ราคาสวนทางไปไกลสุดก่อนไปถูกทาง (MAE)
มัธยฐาน $3.70 · เปอร์เซ็นไทล์ 80 = $12.40 · เปอร์เซ็นไทล์ 90 = $20.60

| SL | โดนเขี่ยทิ้ง |
|---|---|
| $3 | 63% |
| $5 | 43% |
| $10 | 26% |
| $15 | 17% |

### ทำไมต้องเก็บ MFE/MAE ลงฐานข้อมูล

Yahoo ให้แท่ง 5 นาทีย้อนหลังแค่ 60 วัน ถ้าไม่เก็บไว้ อีก 6 เดือนก็ยังวิเคราะห์ได้แค่ 60 วันเท่าเดิม
**ตัวเลขจะไม่มีวันแม่นขึ้น** ตาราง `reactions` จึงเก็บ `up15/dn15/up60/dn60`
= ราคาวิ่งขึ้น/ลงไกลสุดเทียบราคาก่อนประกาศ

เก็บแบบ **ไม่ผูกกับทิศทาง** แล้วค่อยแปลงเป็น MFE/MAE ตอนอ่านตาม `pred` —
ถ้าวันหลังแก้กฎใน `lib/bias.ts` ข้อมูลเก่าจะยังใช้ได้ต่อ ไม่ต้องเก็บใหม่

> ⚠️ ต่างจากขนาด surprise ตรงที่อันนี้ต้องใช้ราคา จึง backfill ได้เฉพาะแถวที่ยังอยู่ในหน้าต่าง 60 วัน
> แถวที่หลุดไปแล้วจะว่างตลอดไป — `/api/collect` รายงาน `withExcursion` ไว้ให้ตรวจ

## สมุดบันทึกเทรด `/journal`

เครื่องมืออื่นทั้งหมดวัด "ตลาด" — อันนี้วัด **"คนเทรด"** ซึ่งมีผลต่อผลลัพธ์ระยะยาวมากกว่า

**นำเข้าได้ 2 ทาง**
- อัปโหลดไฟล์ statement — MT4 (คลิกขวาใน Account History → Save as Report) หรือ MT5 (History → Report)
  รองรับทั้ง HTML และ CSV
- กรอกมือทีละไม้

**ติดป้ายให้อัตโนมัติ** — เซสชัน · เปิดไม้ในช่วง ±30 นาทีรอบข่าวใหญ่ไหม · %เสี่ยงต่อพอร์ต · R · ระยะเวลาถือ

**สรุปให้** — อัตราชนะและกำไรสุทธิ แยกตามเซสชัน / ช่วงข่าว / ระยะเวลาถือ / ทิศทาง / ระดับความเสี่ยง
พร้อมกราฟกระจาย %เสี่ยงรายไม้ (แท่งแดง = เสี่ยงเกิน 10% ของพอร์ตในไม้เดียว)

**แผง "รูปแบบการเล่นของคุณ"** — วัดพฤติกรรม ไม่ใช่ผลงาน จึงอ่านได้ตั้งแต่ไม้ไม่กี่ไม้
เพราะเป็นคำบรรยายสิ่งที่ทำไปแล้ว ไม่ใช่การประมาณค่าขอบได้เปรียบ (ต่างจากอัตราชนะรายกลุ่ม
ซึ่งต้องรอ n เยอะกว่านี้มาก)

| วัดอะไร | ทำไมถึงสำคัญ |
|---|---|
| เข้าใหม่หลังแพ้ vs หลังชนะ | เข้าเร็วกว่ามากหลังแพ้ = ลายเซ็นของการเทรดเอาคืน |
| ระยะเวลาถือ กำไร vs ขาดทุน | ตัดกำไรเร็วกว่าทนขาดทุน = ทิ้งส่วนที่ขอบได้เปรียบอยู่ |
| ซ้อนไม้ทางเดียวกัน | รายงานโชว์ล็อต "ต่อไม้" — เปิด 0.4 สองไม้พร้อมกันคือถือ 0.8 ล็อตจริง |
| กำไรกระจุกที่กี่ไม้ | ตัดไม้ที่ดีสุดออกแล้วพลิกเป็นลบเมื่อไหร่ |
| ตั้ง SL / TP กี่ไม้ | ไม่ตั้ง SL = ความเสี่ยงจริงวัดไม่ได้เลย |

ปิดท้ายด้วยเลขคณิตตรง ๆ: ขนาดที่ถือรวมสูงสุด × ราคาสวน $20 (เปอร์เซ็นไทล์ 90 ของช่วงข่าว)
คิดเป็นกี่ % ของพอร์ต

**แปลงเป็นเงินบาทให้ทุกตัวเลข** — บัญชี cent บอกกำไรเป็น USC ซึ่งอ่านแล้วไม่รู้สึกว่าเยอะหรือน้อย
(591.70 USC ฟังดูเยอะ แต่จริง ๆ คือ ~฿197) ระบบอ่าน**สกุลเงินจากหัวรายงานเอง**
ไม่ต้องตั้งค่า และไม่เดาให้ถ้าอ่านไม่เจอ เพราะเดาผิดระหว่าง USD กับ USC จะคลาดไป 100 เท่า
เรตดึงสดจาก exchangerate-api (สำรอง: frankfurter/ECB) cache 6 ชม. ถ้าดึงไม่ได้จะบอกตรง ๆ ว่าใช้ค่าประมาณ

- **เวลาเซิร์ฟเวอร์โบรกเกอร์ไม่ใช่เวลาไทย** — Exness ใช้ **GMT+0** (ค่าเริ่มต้นของฟอร์ม)
  โบรกอื่นส่วนใหญ่ +2/+3 เช็กได้จากนาฬิกาใน Market Watch ถ้าตั้งผิดเวลาไม้จะเพี้ยนและป้าย
  เซสชัน/ข่าวผิดตาม — แก้แล้วนำเข้าทับได้เลย ใช้เลขที่ออเดอร์เป็นคีย์จึงไม่เกิดรายการซ้ำ
- **รายงาน MT5 เป็น UTF-16** ไม่ใช่ UTF-8 — ตัวอัปโหลดอ่าน BOM แล้วเลือก decoder เอง
  ถ้าใช้ `file.text()` เฉย ๆ จะได้ข้อความเพี้ยนทั้งไฟล์
- **แถวข้อมูลของ MT5 มีช่องซ่อน** `<td class="hidden" colspan="8">` ที่หัวตารางไม่มี
  ถ้าไม่ตัดทิ้ง คอลัมน์ตั้งแต่ Volume จะเลื่อนไป 1 ช่องทั้งหมด
- **ไฟล์เดียวมี 3 ตาราง** (Positions / Orders / Deals) — parser หยุดอ่านเมื่อเจอหัวตารางอันใหม่
- **MT4/MT5 ใช้หัวคอลัมน์ซ้ำ** (`Price` สองอัน, `Time` สองอัน) parser จึงตีความอันที่สองเป็นฝั่งปิด
  ทดสอบแล้วว่าถ้าไม่ทำแบบนี้จะอ่านราคาปิดไม่ได้เลยทั้งสองรูปแบบ
- **%เสี่ยงคำนวณได้ต่อเมื่อตั้ง SL ไว้ในออเดอร์** ถ้าไม่ตั้งจะขึ้นว่า "ไม่ได้ตั้ง SL"

## โหมดข่าว `/live`

หน้าเดียวที่โฟกัสช่วง 30 นาทีรอบข่าวใหญ่ เพราะเป็นช่วงเดียวที่วัดแล้วพบว่ากฎทิศทางได้ผล

- **นาฬิกาสลับเองตอนประกาศ** — ก่อนข่าวนับถอยหลังถึงเวลา พอถึงเวลาเปลี่ยนเป็นนับ
  หน้าต่างขอบได้เปรียบ 15 นาทีถอยหลังจนหมด แล้วบอกตรง ๆ ว่าเข้าตอนนี้ไม่ต่างจากไม่มีข่าว
- **ผลจริงเข้ามาเอง** — ดึงปฏิทินซ้ำทุก 15 วินาทีช่วงใกล้ข่าว (ปกติ 60 วินาที) ไม่ต้องรีเฟรช
- **เทียบกับทฤษฎีสด ๆ** — ราคาก่อนประกาศ → ขยับไปเท่าไหร่ → ทฤษฎีบอกทางไหน → ตรงหรือสวน

**ข้อจำกัดที่ตั้งใจให้เป็นแบบนี้:** หน้าจะขึ้นนาฬิกาเฉพาะข่าวที่เข้าเกณฑ์เดียวกับกลุ่มตัวอย่าง
ที่ใช้วัด 71% (ข่าวแรง · ข่าวใหญ่สหรัฐฯ · ข่าวที่กระทบทองโดยตรง) ถ้าไม่มีก็ขึ้นว่าไม่มี
พร้อมลิสต์ข่าวเล็กแยกไว้ — **ยอมให้หน้าว่างดีกว่าเอาสถิติของข่าวใหญ่ไปแปะกับข่าวเล็ก**

## แจ้งเตือน Telegram

ส่งการ์ดสรุป **ล่วงหน้า 30 นาที** ไม่ใช่ตอนประกาศ เพราะขอบได้เปรียบอยู่ใน 15 นาทีแรก
ถ้าเตือนตอนข่าวออกพอดี กว่าจะหยิบมือถือก็กินหน้าต่างไปครึ่งหนึ่งแล้ว

### 1. สร้างบอท

1. ทัก [@BotFather](https://t.me/BotFather) ใน Telegram → `/newbot` → ได้ token
2. ทักบอทของตัวเองสักข้อความ แล้วเปิด `https://api.telegram.org/bot<TOKEN>/getUpdates`
   เพื่อหา `chat.id`
3. ใส่ `TELEGRAM_BOT_TOKEN` และ `TELEGRAM_CHAT_ID` ลง environment variables

### 2. ทดสอบ

```bash
curl "https://<โดเมน>/api/cron/alert?test=1"   # ส่งข้อความทดสอบเข้า Telegram
curl "https://<โดเมน>/api/cron/alert?dry=1"    # ดูว่าจะส่งอะไรบ้าง โดยไม่ส่งจริง
```

`?dry=1` ตอนไม่มีข่าวในหน้าต่างจะคืนตัวอย่างข้อความมาให้ดูด้วย — จะได้แยกออกว่า
"ไม่มีข่าว" กับ "ระบบพัง" ต่างกันยังไง

### 3. ตั้งเวลาให้เรียกทุก ~10 นาที

**นี่คือส่วนที่ต้องตัดสินใจ** — Vercel แผนฟรีรัน cron ได้วันละครั้ง ซึ่งไม่พอ

| วิธี | ความเที่ยง | หมายเหตุ |
|---|---|---|
| **[cron-job.org](https://cron-job.org)** (แนะนำ) | ดี | ฟรี ยิงได้ทุกนาที ใส่ header `Authorization: Bearer <CRON_SECRET>` |
| GitHub Actions | ปานกลาง | ไฟล์ [`.github/workflows/alert.yml`](.github/workflows/alert.yml) พร้อมใช้ แต่ cron ของ GitHub ดีเลย์ 10-20 นาทีได้ |
| Vercel Pro | ดี | เพิ่ม `{"path": "/api/cron/alert", "schedule": "*/10 * * * *"}` ใน `vercel.json` |

**กันส่งซ้ำ** — เก็บ `<event id>:pre` ลงตาราง `alerts_sent` ใน Turso จึงยิงเข้ามาถี่แค่ไหน
ก็ไม่โดนข้อความเดิมรัว ๆ และบันทึกเฉพาะที่ส่งสำเร็จ ถ้าล้มเหลวรอบหน้าจะลองใหม่เอง
ถ้าไม่ได้ตั้ง Turso ระบบจะยังส่งได้แต่ **กันซ้ำไม่ได้** และบอกไว้ใน response ตรง ๆ

## อินดิเคเตอร์ TradingView (Pine Script)

ไฟล์ [`pine/gold-levels.pine`](pine/gold-levels.pine) คืออัลกอริทึมแนวรับแนวต้านชุดเดียวกับเว็บ
แต่รันบน TradingView โดยตรง

**ทำไมถึงดีกว่าดูในเว็บตอนเทรดจริง**

| | เว็บ | Pine บน TradingView |
|---|---|---|
| ราคา | PAXG/GC=F ปรับฐาน คลาด ±$1-2 | **ฟีดของกราฟนั้นเอง ไม่คลาดเลย** |
| อัปเดต | ทุก 1 นาที (static page) | **เรียลไทม์** |
| ใช้ตอนไหน | วางแผนก่อนเทรด | **ขณะเทรด** |

### วิธีติดตั้ง

1. เปิด TradingView → กราฟ **XAUUSD timeframe 15 นาที**
2. เมนูล่าง **Pine Editor** → **Open** → **New indicator**
3. ลบโค้ดตัวอย่างทิ้ง แล้ววางเนื้อหาทั้งหมดของ `pine/gold-levels.pine`
4. กด **Save** ตั้งชื่ออะไรก็ได้ → กด **Add to chart**

ปรับค่าได้ที่ไอคอนเฟือง — เปิด/ปิดแยกได้ทุกกลุ่ม (โซนกลับตัว / Pivot / กรอบเอเชีย / เลขกลม)

### สิ่งที่ต้องคาดหวัง (ไม่ใช่บั๊ก)

- **ตัวเลขไม่ตรงกับเว็บเป๊ะ** เพราะคนละฟีดราคา — ตัวบน TradingView คือตัวที่ตรงกับกราฟที่คุณกดออเดอร์
- **Pivot รายวันอาจต่างจากเว็บ** เพราะ TradingView นับ "วัน" ตามเวลาตลาด ส่วนเว็บนับตามวันไทย
  ของ TradingView ตรงกับที่เทรดเดอร์ทั่วโลกดู จึงเป็นมาตรฐานกว่า
- **โซนกลับตัวอาจต่างจากเว็บเล็กน้อย** — วัดจริงแล้วต่างสูงสุด **$0.33** (เล็กกว่าความกว้างโซน $3.5 มาก)
  เพราะ `ta.pivothigh` ของ Pine เทียบแบบเข้มงวด (`>`) ส่วนเว็บยอมให้ราคาเท่ากันได้ (`>=`)
- **จุดกลับตัวยืนยันช้า 3 แท่ง** (45 นาทีบน TF 15m) เป็นธรรมชาติของ fractal เว็บก็เหมือนกัน

### ตรวจว่าทำงานถูก

วิธีที่ดีที่สุดคือเทียบกับของที่ TradingView คำนวณเอง — เพิ่มอินดิเคเตอร์
**Pivot Points Standard** (ตั้ง Type = `Classic`, Pivots Timeframe = `Daily`)
แล้วดูว่าเส้น PP / R1 / R2 / S1 / S2 **ทับกันสนิท**

### จุดที่ต้องระวังถ้าจะแก้โค้ด

- **เวลาไทย** — Vercel รันด้วย UTC เสมอ `lib/time.ts` จึงบวก offset เองแล้วอ่านด้วย `getUTC*`
  อย่าใช้ `toLocaleString` กับ timezone ของเซิร์ฟเวอร์
- **TradingView ตัดข้อมูลเงียบ ๆ** ถ้าขอช่วงยาวเกิน — ดึงย้อนหลังไกลต้องใช้ `fetchRange()` ที่วนทีละ 60 วัน
- **แนวรับแนวต้านต้องใช้ PAXG ไม่ใช่ GC=F** — ฟิวเจอร์สแพงกว่า spot ~$35 เส้นจะเพี้ยนทั้งกระดาน
  แต่ Reaction Lab ใช้ GC=F ได้เพราะวัดแค่ส่วนต่าง
- **การจับกลุ่มโซนแนวรับ** ต้องเทียบกับราคาเริ่มโซน ไม่ใช่จุดก่อนหน้า ไม่งั้นจุดจะต่อกันเป็นลูกโซ่
- **ห้ามโชว์ % จากตัวอย่างน้อยกว่า 3 ครั้ง** — `MIN_SAMPLE` ใน `lib/reactions.ts`
- **ห้าม hardcode ยอดเงิน** — อ่านจาก `loadAccount()` เสมอ ยอดเปลี่ยนทุกครั้งที่เทรด
- **เวลาอ่านป้ายกำกับในรายงาน ต้องบังคับให้มี `:`** — ในไฟล์มีคำว่า "Balance" ลอย ๆ
  อยู่ก่อนป้ายจริง ถ้าปล่อยให้โคลอนเป็น optional จะไปแมตช์ตัวนั้นแล้วได้ค่าว่าง (เคยพลาดมาแล้ว)
- **`hold_min = 0` เป็นค่าที่ถูกต้อง ไม่ใช่ค่าว่าง** — ไม้ที่เปิดปิดในนาทีเดียวมีจริง
  ถ้าเช็กด้วย `t.hold_min ? ... : null` จะตกไม้นั้นและทำให้มัธยฐานเพี้ยน (เคยพลาดมาแล้ว)
- **ห้ามบอกว่า "กินได้" จากค่าเฉลี่ยบวกอย่างเดียว** — ต้องดูขอบล่างของช่วงความเชื่อมั่น
  และต้องโชว์มัธยฐานคู่กับค่าเฉลี่ยเสมอ ไม่งั้นการกระจายแบบหางยาวจะถูกซ่อน
- **นิยามใน `lib/regime.ts` ห้ามเพี้ยน** — ตัวเลข 68.8%/44.2% ผูกกับนิยามที่ใช้ตอนวัด
  ถ้าเปลี่ยนสูตร ATR หรือหน้าต่างความเร็ว ตัวเลขที่แปะไว้จะไม่ใช่ของสภาพนั้นอีกต่อไป
- **`/api/tcheck` คือชุดทดสอบของโปรเจกต์นี้** (ยังไม่มี test runner) รันด้วย
  `curl http://localhost:3000/api/tcheck` ก่อน commit ทุกครั้ง
